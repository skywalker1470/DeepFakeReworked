# Deepfake Detector — Cloud Deployment

A cloud-deployed version of the existing Deepfake Detection System. The model is wrapped in a REST API, containerized with Docker, deployed to AWS EC2, and the whole build-deploy-test cycle is automated with a Bash script.

This project takes an existing trained model and turns it into a real, callable cloud service — the goal is to demonstrate REST API design, containerization, cloud deployment, and automation end to end.

## Why this project

Most of my past work has focused on building and evaluating models. This project focuses on the other half: taking a working model and shipping it as a real service. It covers:

- REST API design and system integration
- Containerization with Docker
- Cloud deployment on AWS
- Automation scripting with Bash

## Instance sizing note

The service runs on a `t3.micro` (AWS free tier — 1 vCPU, 1GB RAM). Measured locally, loading both models (EfficientNet-B0 classifier + YOLOv8n-face detector) on CPU takes ~700MB RSS before handling a single request — tight on a 1GB instance. A 2GB swapfile was added on the instance as a safety margin against OOM kills under load. This is acceptable for a low-traffic portfolio demo; a real-traffic deployment would need a bigger instance (`t3.small`/`medium`) rather than relying on swap.

Oracle Cloud's Always Free Ampere A1 (ARM, up to 4 cores/24GB RAM, not time-limited) was considered as a way to sidestep this RAM constraint entirely, but its free-tier ARM capacity was unavailable at signup time in practice — a common issue with that tier. AWS EC2 free tier was used instead, accepting the swap-based mitigation above.

        ▼

## Tech Stack

- **Model**: EfficientNet-B0 (transfer learning), YOLOv8n-face for face detection, frame-level video inference
- **API**: FastAPI
- **Containerization**: Docker
- **Cloud**: AWS EC2 (t3.micro, free tier)
- **Automation**: Bash script for build, push, deploy, and smoke-test

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/health` | Health check, returns service status |
| `POST` | `/predict` | Accepts a video file, returns prediction (real/fake) with confidence score |
| `GET` | `/metrics` | Returns basic usage stats (request count, avg latency) |

Example request:
```bash
curl -X POST "http://<host>:8000/predict" \
  -F "file=@sample_video.mp4"
```

Example response:
```json
{
  "prediction": "fake",
  "confidence": 0.91,
  "frames_analyzed": 24,
  "inference_time_ms": 340
}
```

## Docker

Build and run the container locally:
```bash
docker build -t deepfake-detector .
docker run -p 8000:8000 deepfake-detector
```

## AWS Deployment

1. Launch a `t3.micro` EC2 instance (Ubuntu LTS AMI, free tier eligible).
2. Open the security group: inbound TCP 22 (SSH, restricted to your IP) and TCP 8000 (API, `0.0.0.0/0`).
3. Add a 2GB swapfile on the instance (see readme.md for the exact commands) — mitigates OOM risk given the 1GB RAM ceiling.
4. Install Docker on the instance and add the login user to the `docker` group.
5. Pull the image and run the container, exposing port 8000.

## Automation Script (`deploy.sh`)

The script automates the full cycle:
1. Build the Docker image
2. Tag and push it to a container registry (Docker Hub)
3. SSH into the EC2 instance and pull the latest image
4. Restart the container
5. Run a smoke test against `/health` to confirm the deployment succeeded

```bash
./deploy.sh
```

A GitHub Actions workflow (`.github/workflows/deploy.yml`) runs this same flow automatically on every push to `main`, using repo secrets (`REGISTRY`, `DOCKERHUB_TOKEN`, `VM_HOST`, `VM_KEY`) for credentials.

## Testing

- Unit tests for the API endpoints (`tests/test_api.py`)
- A smoke test script that hits `/health` and `/predict` with a sample video after every deployment
- Manual test: run a known real and a known fake video through the deployed endpoint and confirm expected predictions
